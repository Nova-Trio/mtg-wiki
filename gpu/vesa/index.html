VESA BIOS Extensions

If you are targeting a BIOS or a BIOS compatible (CSM) motherboard and dont want UEFI a reliable method of setting a video mode is by using VESA BIOS Extensions, you can read about the standard here,

Getting SuperVGA Information

By calling interrupt 10 with function 0x4F00 with a 512 byte return buffer in ES:DI you will get

AL 0x4F if function supported
AH 0x00 = successful
else = error code

If successful your buffer will contain:

Offset Size Description
0x00 4 bytes Signature ("VESA" returned; pass "VBE2" before call to request VBE 2.0+ info)
0x04 WORD VESA version number (e.g. 0x0200 = v2.0)
0x06 DWORD Pointer to OEM string
0x0A DWORD Capabilities flags (see below)
0x0E DWORD Pointer to list of supported VESA and OEM video modes (terminated with 0xFFFF)
0x12 WORD Total amount of video memory in 64K blocks
0x14 WORD OEM software version (BCD, high byte = major, low byte = minor)
0x16 DWORD Pointer to vendor name string
0x1A DWORD Pointer to product name string
0x1E DWORD Pointer to product revision string
0x22 WORD VBE/AF version (if capabilities bit 3 set)
0x24 DWORD Pointer to list of supported accelerated video modes (if capabilities bit 3 set)
0x28 216 bytes Reserved for VBE implementation
0x100 256 bytes OEM scratchpad

Capabilities flags

Bit(s) Description
0 DAC can be switched into 8-bit mode
1 Non-VGA controller
2 Programmed DAC with blank bit (i.e. only during blanking interval)
3 Controller supports hardware stereoscopic signalling (VBE 3.0) / VBE/AF extensions
4 Stereo signalling type (VBE 3.0) / Must call EnableDirectAccess to access framebuffer (VBE/AF)
5 Controller supports hardware mouse cursor (VBE/AF)
6 Controller supports hardware clipping (VBE/AF)
7 Controller supports transparent BitBLT (VBE/AF)
8-31 Reserved
QEMU Uses Bochs VBE as default video adapter which implements version VBE 2.0, you can use it via a PCI driver or via interrupts

Getting Video Mode Information

Function 0x4F00 only returns a list of mode numbers to get the resolution, color depth, framebuffer address of a specific mode, call interrupt 10 with function 0x4F01 and pass the mode number in CX and a 256 byte return buffer in ES:DI.

AX 0x4F01
CX Video mode number to query
ES:DI Pointer to 256 byte return buffer

Return:

AL 0x4F if function supported
AH 0x00 = successful
0x01 = failed

If successful your buffer will contain:

Offset Size Description
0x00 WORD Mode attributes (see below)
0x02 BYTE Window A attributes
0x03 BYTE Window B attributes
0x04 WORD Window granularity in KB
0x06 WORD Window size in KB
0x08 WORD Start segment of window A (0000h if not supported)
0x0A WORD Start segment of window B (0000h if not supported)
0x0C DWORD Pointer to FAR window positioning function
0x10 WORD Bytes per scan line (pitch/stride)
0x12 WORD Width in pixels (graphics) or characters (text)
0x14 WORD Height in pixels (graphics) or characters (text)
0x16 BYTE Width of character cell in pixels
0x17 BYTE Height of character cell in pixels
0x18 BYTE Number of memory planes
0x19 BYTE Bits per pixel (bpp)
0x1A BYTE Number of banks
0x1B BYTE Memory model type (0x04 = packed pixel, 0x06 = direct color)
0x1C BYTE Bank size in KB
0x1D BYTE Number of image pages (less one)
0x1E BYTE Reserved (0x00 for VBE 1.0–2.0, 0x01 for VBE 3.0)
0x1F BYTE Red mask size in bits (VBE 1.2+)
0x20 BYTE Red field bit position (VBE 1.2+)
0x21 BYTE Green mask size in bits (VBE 1.2+)
0x22 BYTE Green field bit position (VBE 1.2+)
0x23 BYTE Blue mask size in bits (VBE 1.2+)
0x24 BYTE Blue field bit position (VBE 1.2+)
0x25 BYTE Reserved mask size in bits (VBE 1.2+)
0x26 BYTE Reserved field bit position (VBE 1.2+)
0x27 BYTE Direct color mode attributes
0x28 DWORD Physical base address of linear video buffer (LFB) (VBE 2.0+)
0x2C DWORD Pointer to start of offscreen memory
0x30 WORD Offscreen memory size in KB
0x32 WORD Bytes per scan line in linear modes (VBE 3.0)
0x34 14 bytes Linear mode color mask sizes, positions, and clock fields (VBE 3.0)
0x42 190 bytes Reserved (0)

Mode attributes

Bit(s) Description
0 Mode supported by present hardware configuration
1 Optional information available (must be 1 for VBE 1.2+)
2 BIOS output supported
3 1 = Color mode, 0 = Monochrome mode
4 1 = Graphics mode, 0 = Text mode
5 Mode is not VGA-compatible (VBE 2.0+)
6 Bank-switched mode not supported (VBE 2.0+)
7 Linear framebuffer mode supported (VBE 2.0+)
8 Double-scan mode available (VBE 2.0+)
9-15 Reserved / advanced features (interlaced, stereoscopic, triple buffering)

Setting a video mode

Setting a mode is very easy, interrupt 10 with function 0x4F02 and by passing your video mode in BX OR if you have a VBE 3.0+ support you can pass a CRTC block in ES:DI

CRTC Information Block

Offset Size Description
0x00 WORD Total number of pixels horizontally (HTotal)
0x02 WORD Horizontal sync start (in pixels)
0x04 WORD Horizontal sync end (in pixels)
0x06 WORD Total number of scan lines (VTotal)
0x08 WORD Vertical sync start (in scan lines)
0x0A WORD Vertical sync end (in scan lines)
0x0C BYTE Flags (see below)
0x0D DWORD Pixel clock, in Hz
0x11 WORD Refresh rate in 0.01 Hz units (MUST be set to pixel_clock / (HTotal * VTotal))
0x13 40 bytes Reserved

CRTC flags

Bit(s) Description
0 Double scan (0 = disabled, 1 = enabled)
1 Interlaced (0 = non-interlaced, 1 = interlaced)
2 Horizontal sync polarity (0 = positive, 1 = negative)
3 Vertical sync polarity (0 = positive, 1 = negative)
4-7 Reserved (0)

VBE/AF (Accelerator Functions)

Emulators like QEMU do not emulate this, it is designed to provide 2D acceleration for common functions like line draw, bitblt, hardware cursor, etc by calling function pointers in protected mode

Support for VBE/AF is indicated in the VBE 2.0 SuperVGA Information Block (function 0x4F00):

Field Offset Description
Capabilities Bit 3 0x0A If set (1), the controller supports VBE/AF extensions
VBE/AF Version 0x22 BCD version of the specification (e.g. 0x0100 for v1.0P)
Accelerated Modes 0x24 32-bit far pointer to a list of mode numbers supporting acceleration (0xFFFF terminated)
