Graphics in your OS

There are many ways to implement graphics in your OS, we will go over each and talk about pros and cons, avoid what people tell you to implement, choose whichever you want since we provide tutorials and documentation on almost all of these

Firmware provided

Very easy to implement, high resolutions and color depths

UEFI GOP (Graphics Output Protocol)

When targeting UEFI you can use the EFI_GRAPHICS_OUTPUT_PROTOCOL before exiting boot services. It supports setting high resolutions, 32bit color (R8G8B8A8 or B8G8R8A8) and gives you the width, height, pitch (stride), base address and a pixel format. It is a linear framebuffer

Pros: Standard across all modern UEFI systems, easy to implement

Cons: Fully CPU based rendering, changing resolutions only works before exiting boot services


VESA BIOS Extensions

When targeting BIOS you can invoke INT 0x10 functions 0x4F00, 0x4F01, 0x4F02 to probe modes and set a high resolutions LFB (Linear Framebuffer)

Pros: Works on almost all legacy machines

Cons: Fully CPU based rendering, must be initialized before switching to 32bit/64bit or via v86 mode

Legacy VGA hardware

As mentioned above, only works on legacy hardware, very easy to implement but very limited

VGA Text Mode (mode 0x03)

Each character takes 2 bytes, video memory is at 0xB8000, 80x25 character resolution

Pros: Very simple, works on any BIOS/CSM machine

Cons: Text only


BIOS Mode 0x13

Set via INT 0x10 function 0 mode 0x13, you get a 320x200 256 color mode at address 0xA0000.

Pros: Very easy

Cons: Very low resolution and color


VGA Register Programming

By writing to VGA IO ports 0x3C0 - 0x3DF you can set some custom modes and use some features like hardware page flipping

Pros: No need for BIOS interrupts

Cons: A bit tedious

Virtualized & Paravirtualized Display cards

Easy to implement and provides some level of control over your graphics stack, can get 3D and 2D acceleration

BGA (Bochs Graphics Adapter)

Supported in QEMU, Bochs and VBox, it is a PCI device. Requires writing to IO ports 0x01CE and 0x01CF or the PCI BAR registers, framebuffer address is in BAR1

Pros: Can dynamically change resolution and bit depth (upto 32bpp), easy to implement

Cons: CPU based rendering, virtualized device


VirtIO-GPU

Supported in QEMU on Linux, maybe it works on Windows version on QEMU, Paravirtualized device, allows 3D hardware acceleration via VirGL which are translated and sent to your host GPU for execution. Uses standard VirtIO queues, it is a PCI device.

Pros: Fully virtualized 2D and 3D graphics

Cons: It is a paravirtualized device, your OS depends on VirGL


VMware SVGA-II

Works the best in VMware, QEMU and VBox support it but it is not the best, good 2D hardware acceleration (hardware cursor, hw blitting), some 3D acceleration, it is a PCI device too.

Pros: 3D & 2D acceleration

Cons: Paravirtualized device, works best on VMware


Hardware GPU Support

The best choice for full 3D, 2D acceleration, hardware acceleration for video decode/encode and much more. Requires you to either pass your gpu via VFIO or boot on real hardware, all modern GPUS have some kind of on board security and firmware requirement. A very good reminder is that there is no need to buy obsolete cards to make drivers for if your OS will be for a modern PC.

NVIDIA

Tedious but not impossible, while the card is propreitery you can get new cards (Turing+) to work but you cant take shortcuts or try to cut corners in the driver because of the security, older architectures (Pascal-) mostly use MMIO and some security engines

Pros: Full hardware acceleration support, support for modern graphics apis

Cons: Tedious


AMD Radeon (AMDGPU)

More open compared to NVIDIA, requires multiple firmware binaries, less tedious but still very possible

Pros: Full hardware acceleration support, support for modern graphics apis

Cons: Tedious


Intel UHD / HD / Iris

Open documentation by Intel, only one to not require signed firmware for modesetting, firmware is required for video encode/decode, graphics acceleration (Gen 12+) and power managment on newer architectures.

Pros: Full hardware acceleration support, support for modern graphics apis

Cons: Less tedious


Intel Arc

Firmware is required to use the card, same requirement as others

Pros: Full hardware acceleration support, support for modern graphics apis

Cons: Tedious
